## 3. 代码编写步骤

脚本按“参数 → 建模型 → 仿真 → 分析 → 出图 → 出报告 → 出日志”的顺序组织，主要步骤：

1. **参数集中定义**：船舶模型参数 K、T，控制器增益 Kp/Ki/Kd，采样周期、求解步长、仿真时长、舵角限幅、航向序列与判据阈值统一放入 `prm` 结构体，便于复现与修改。
2. **模型初始化**：`new_system` 创建模型，配置 ode4 定步长求解器与信号记录开关。
3. **主回路搭建**：依次添加 Clock、两个零阶保持器（ZOH）、MATLAB Function 状态机、Sum 误差模块、PID Controller、USV_Plant 子系统、Mux 与 Scope，并完成连线。
4. **状态机实现**：在 MATLAB Function 模块中写入带 persistent 变量的三阶段切换逻辑，使用仿真时间累计稳定保持时长，避免对采样周期的硬编码依赖。
5. **船舶模型搭建**：在 USV_Plant 子系统内用 Gain、Sum、两个 Integrator 实现 T·dr/dt + r = K·δ 与 dψ/dt = r，同时输出 ψ 与 r。
6. **PID 参数配置**：离散化（Ts = 0.05 s）、并联型、输出限幅 ±30°、clamping 抗积分饱和、以 r 作为外部微分输入。
7. **信号记录**：对 6 路关键信号所在输出端口开启 DataLogging 并命名，仿真后通过 `out.logsout` 统一提取。
8. **指标计算**：将各信号重采样到统一步长网格，按阶段统计收敛时刻、稳定保持时长、上升时间、超调量、稳态误差、最大舵角与最大转艏角速度。
9. **报告与日志**：使用 MATLAB Report Generator 的 DOM 接口生成 docx（含参数表、模块表、三张曲线图与收敛数据表），用 UTF-8 编码写出本工作日志。

## 4. 遇到的问题与解决方法

1. **信号记录接口不匹配**：直接对信号线对象设置 `DataLogging` 参数会报“line 没有该参数”。改为对源模块的输出端口（`PortHandles.Outport`）设置 `DataLogging`、`DataLoggingNameMode`、`DataLoggingName`，日志通过 `out.logsout.get(name)` 读取，稳定可靠。
2. **期望航向阶跃引起微分冲击**：若对误差直接微分，30°→230° 的指令阶跃会在切换瞬间产生巨大的微分脉冲，导致舵角瞬时反复饱和。解决方法是把船舶转艏角速度 r 接入 PID 的“外部微分输入”，实现微分作用于测量值，切换过程平滑。
3. **大角度转向的积分饱和**：200° 阶跃时误差长时间较大，积分项累积会造成明显超调。通过 PID 输出限幅 ±30° 并启用 clamping 抗饱和，超调量被控制在较小范围。
4. **报告中文显示与排版**：docx 由 Report Generator DOM 接口生成。其导出字体只写入 ascii/hAnsi，缺少 eastAsia 声明，Word 会回退到日文字体（MS Mincho），造成中文字形混排；因此增加一步 document.xml 后处理，为宋体/微软雅黑补写 `w:eastAsia`。曲线图按 15 cm 宽等比缩放插入，避免超出版心。
5. **MATLAB Function 模块的采样时间约束**：状态机用 persistent 变量记录阶段号与稳定保持计时，模块若继承连续采样时间会报“persistent 变量要求非继承采样时间”。解决方法是给状态机的两路输入各加一个 0.05 s 的零阶保持器，使模块继承离散周期；保持计时改用仿真时间差，避免对采样周期硬编码。
